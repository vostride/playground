# Implementation audit

Audited against `SPEC.md` on 2026-10-18. This records source, local, and GitHub CI evidence; deployment and release publication are tracked separately. Only files in this repository were changed. Native release builds were not run on the developer machine.

## Outcome

The four web products, their shared product models, and the four native product screens are implemented. The current names are **Komazon**, **Looking**, **PepaPog**, and **Brello**. Earlier native revisions compiled on GitHub runners; the renamed native source has passed TypeScript and Metro checks but has not yet completed a fresh native build and device acceptance. Complete native acceptance, the hosted custom domain, and published immutable release assets remain outstanding. The registry labels the web apps as candidates and has no invented mobile release entries.

## Current redesign and local verification

The app directory is a compact launcher with product names and logos. Each web app starts on its core working screen. Marketing heroes, promotional cards, slogans, decorative introductions, and redundant footers have been removed; checkout and empty-state copy uses functional headings.

The current checkout uses locally owned official shadcn/ui components from the `new-york-v4` registry, Tailwind CSS, and self-hosted Inter variable fonts in all four web builds. The dark treatment covers every product view and form, with transparent sections, divider rules, brighter text, and stronger headings. Rectangular controls use 0–2px corners. Compact spacing replaces enclosing panels, while Komazon retains a responsive product grid and Brello uses small bordered cards for draggable tasks. Product styles use `@layer product`, while semantic component utilities remain shared. Original vector logos identify all four products in the directory and web headers; matching native PNG assets are bundled locally. Paths, storage keys, and automation IDs remain stable.

Looking’s web calendar has month/year navigation and exact date entry through **Use date**. Valid dates in years 0001–9999 are supported, leap days are validated, and return-before-departure input is rejected. The selected dates propagate to search results rather than being restricted to the seed month.

An independent sub-agent audited the visible copy across web/native screens, secondary flows, metadata, help and the 404 page. Simulation notices and promotional copy are removed. Functional form help, data, errors and test controls remain. Native route assertions now target functional headings or stable identifiers.

Local verification after the redesign and rename passed **29 browser tests**, including five date regressions and landscape dialog focus; **27 core tests**; **17 native helper tests**; **12 Maestro YAML validations**; web/native TypeScript; all four Vite builds; and both Metro JavaScript bundles, each containing all four brand assets. Desktop and narrow-layout visual review accompanies these checks. These are local checks of the current source, not evidence of a new deployed site, native artifact, or release. The small keyboard-order change described below passes source/helper validation and still needs device execution.

The historical CI records below retain the product names used by those runs: Fernwood is now Komazon, Wayline is Looking, Vigil is PepaPog, and Corkboard is Brello. Prior binary results do not automatically verify the renamed source.

## Platform layout and expanded native acceptance

Commit `8f74c2b` moves the four browser projects to `web/` and React Native to `mobile/`, retaining shared packages at the root. Workspace links, native dependency paths, build tooling, Tailwind source paths and CI artifact paths were updated. Dependency versions and integrity hashes are unchanged. Local checks passed: 29 browser cases, both TypeScript targets, all four web builds and both Metro bundles. Brello’s cards and connected heading dividers were visually checked at 1440 and 390 pixels; Looking’s title and wordmark use the shortened name.

The native harness now includes catalog/list refresh, both switches per product, exact totals, persisted task properties, monitor edits, navigation, cross-product reset and process restart coverage. These test-only additions preserve the current candidate’s application source fingerprint. The shared iOS helper was corrected after the pinned Maestro parser left regex dollar anchors inside an expression as literal text. A regression validator checks all YAML interpolation before CI.

Android full-suite CI now requires observed offline connectivity before and after the product journeys. Native touch and URL checks run even after a Maestro failure so their separate evidence is retained; any failed check still fails the gate. The expanded journeys and offline checks still require actual runtime execution. iOS offline isolation remains an open verification item.

## Corrections found and addressed during this audit

- **Release contract guard:** `web.yml` now fetches history and compares the registry against the PR base or prior push commit. The registry script validates the baseline, protects released entries, and checks released test-file SHA-256 values. A malformed baseline is no longer silently treated as a first release.
- **Looking parity:** native filters now match the web defaults and options, including multiple airlines and afternoon departures. Web booking management now edits seats on both outbound and return legs. Native routing observes warm deep-link changes.
- **Komazon parity:** native search now includes product color; native price filters, rating sort, and the same country choices are present. Product details scroll on smaller screens.
- **Brello touch reachability:** native drag now continuously scrolls at both horizontal and vertical viewport edges. Accessible move actions and explicit move-earlier/move-later controls are also available. Android's verified downward drag includes vertical edge scrolling; the iOS ordinary reorder and cross-column gestures have passed on an earlier binary.
- **Brello keyboard reachability:** moving with the keyboard respects hidden completed columns, avoiding a move into an invisible destination that could strand keyboard focus.

- **Brello rapid keyboard movement:** a delayed animation frame could leave focus on the document after moving a card, losing the final Space press. Focus now restores during layout; the regression delays animation frames and verifies placement, undo, and Escape rollback.
- **Native card drafts:** closing or moving a card now flushes text drafts explicitly; undoing the move preserves the edited title.
- **Native drag coordinates:** Android's held drag activated but failed to save a visible drop. The native code mixed React-root touch coordinates with window-relative measurements. All three drag measurement sites now use root-relative `View.measure` coordinates for hit testing, edge scrolling, and the drag preview. Native typechecking, 11 relevant core/harness tests, and real Android reorder/cross-column/Undo checks pass. iOS diagnostic `39140383901` also verifies both gestures on the corrected source-matched binary. A future release still has to run the checks on its exact artifact.
- **Native system insets:** the shell and each modal now use native safe-area providers and views so Android edge-to-edge system bars cannot cover controls.
- **Production static routing:** exact directory redirects preserve JavaScript assets; a labelled 404 disables implicit SPA fallback. The preview server exercises the deployed headers and routing rules.
- **Native keyboard dismissal:** forms expose a keyboard-visible “Done typing” action; single-line fields submit with Done. Acceptance helpers wait for the control to disappear after dismissal.
- **Task-sheet keyboard accessibility:** the modal accessibility boundary now includes the safe-area keyboard toolbar. Previously iOS displayed the button but excluded its sibling subtree from accessibility queries. Typechecking passes; the corrected native candidate still needs runtime verification.
- **Independent iOS URL coverage:** Maestro business journeys now use the visible tabs, product controls, task search, and bug switch. A mandatory XCTest companion exercises native URLs and warm query state through Apple's direct-target API. Both gates must pass; this does not claim coverage of SpringBoard's first-link chooser, whose intermittent delivery failure is preserved in earlier diagnostics.
- **Native scroll target visibility:** flow selectors account for fixed navigation at both ends of the content viewport. Retained iOS screenshots exposed centered scrolling that could move an already visible field behind the top navigation; those taps are corrected with explicit value assertions.
- **Android runner setup:** installation no longer requests the retired SDK `tools` package, and the version code is parsed as an integer before assignment to the Gradle DSL.
- **Workspace Hermes compiler:** Android explicitly resolves the compiler in the repository's hoisted `node_modules`; Gradle's package-local default could bundle JavaScript but could not compile it to Hermes bytecode.
- **Merged APK inspection:** release and diagnostic workflows share a validator for app identity, permission declarations and requests, and native architectures. It preserves AndroidX's app-owned signature receiver protection while rejecting every system permission and other custom request.
- **Continuous native drag checks:** Android uses held `draganddrop` input and iOS uses an XCTest press-and-drag. Both check reordering, movement across columns, and undo. Runtime passes are recorded above; the final release must run these gates again on its exact binaries.

## Platform and distribution source checks

- Native app registration, Android activity component name, iOS factory module name and `app.json` consistently use `Playground`.
- Android namespace/application ID and iOS bundle ID use `dev.vostride.playground`; both register the same deep-link scheme.
- Monorepo paths in Android settings/build configuration, CocoaPods resolution and Metro configuration point to the shared workspace dependencies.
- The installed React Native package requires Xcode 16.1 or newer and iOS 15.1; the workflow selects Xcode 16.4 and the project targets iOS 15.1.
- The release workflow requests an unsigned simulator build for `arm64 x86_64`, wraps `Playground.app` in a ZIP, checks both SHA-256 files before publication, and refuses existing release tags twice.
- The attestation action and permission names match the current [official `actions/attest` documentation](https://github.com/actions/attest).
- `continue-on-error: true` is applied to the deployed-preview site check, allowing its report to expose failures without blocking production as specified. Pre-deployment local product regressions remain normal CI checks.

## Evidence limitations

Local TypeScript/core tests and Metro bundles cannot validate native platform linking or gestures. The existing browser report does not prove the hosted site is live. This audit did not infer success from workflow YAML, placeholder release metadata, or inaccessible remote endpoints. Actual deployment and release evidence should be appended after those operations complete.
